## Problem

The v2 gate had three routes: `exempt`, `visual` (BBEdit approval) and
`pangram` (a Pangram check record plus BBEdit approval). Andrew named four
problems on 2026-10-22:

- Pangram cost money, and its "is this AI?" verdict added nothing. Any
  verdict passed; the record only proved the check ran.
- Approval needed BBEdit on a GUI desktop. It failed from SSH, cloud or
  phone.
- No deterministic prose checks existed beyond character caps. Dash bans,
  phrase lists and sentence length lived only as prose in personify.
- Beacon coverage had holes: code comments, docs, Slack and Asana, and
  several `gh` forms.

## Decisions (Andrew, 2026-10-22)

1. Pangram leaves the gate. personify becomes a plain style and voice
   advisor; its MCP server stays for cloud agents.
2. Routes are `review | exempt`. Any other outcome is a rules error, so the
   gate fails closed.
3. Deterministic lint runs everywhere. Exempt routes get warnings. Review
   routes block, and an override needs a stated reason.
4. Approval by any one channel: local editor, `approve <code>` in chat, or a
   GitHub draft PR that Andrew marks ready himself.
5. Beacon commit messages: lint at commit; approval happens in the draft PR.
6. `andrewmrich/*`: exempt if private, review if public. A failed visibility
   lookup counts as review.
7. Slack and Asana: agents have no write access, so all such text is a draft
   Andrew posts. No hook work; agents lint the draft before showing it.

## CI-only test suites (same day)

Not part of the gate design, but it shipped in the same window and changed
how agents test:

1. `claude-config#774` and `dotfiles#462` made the full suites refuse outside
   CI, and #774 added a required hook that blocked full-suite commands.
   `dev-env#223` made the three dev-env tool runners CI-only too.
2. The hook blocked far more than the full suites (`npm test`, `make test`,
   bare `pytest`, and suite commands quoted in commit text). `claude-config#775`
   removed it. The runner guard in claude-config and dotfiles stays, and
   `RUN_FULL_SUITE=1` (`dotfiles#463`, `claude-config#775`) is Andrew's
   override for hand runs. Agents never set it.
3. `dev-env#224` reverted #223. Those runners take seconds, and Andrew
   wanted only the claude-config and dotfiles full suites blocked. dev-env
   tool suites run locally again.

## Boundary

Hooks cover Claude Code sessions only. Text drafted in Claude Desktop or
claude.ai is not gated.
